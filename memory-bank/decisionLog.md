## Решение: Навигационная структура сводной страницы

**Принято:** 2026-05-12 22:57:00

**Обоснование:** Разделение ответственности между информацией и действиями.

**Детали реализации:**
- **Карточки пилотов** (блок "Четыре формата") → ведут на основные страницы (`./advisor/`, `./circle/`, `./mvp/`, `./operator/`)
- **CTA-кнопки** (блок "Начни с пилота") → ведут на формы заявок (`./advisor/apply.html`, `./circle/apply.html`, `./mvp/apply.html`, `./operator/apply.html`)
- **Hero-кнопки на страницах пилотов** → ведут на формы заявок (`./apply.html`)

**Результат:** Ясный поток: сводная → информация → заявка.

## Решение: Единообразный стиль CTA-кнопок

**Принято:** 2026-05-13 00:00:50

**Обоснование:** Все CTA-кнопки на сводной странице должны быть одинакового приоритета.

**Детали реализации:**
- Все 4 кнопки в CTA-блоке используют класс `.button-primary` (зелёный gradient, как у Advisor).
- Расположены в 2×2 grid для мобильной адаптации.

**Результат:** Визуальная иерархия ясна: приглашение участвовать имеет одинаковый вес для всех пилотов.

## Решение: Создание форм заявок для всех пилотов

**Принято:** 2026-05-12 22:44:07

**Обоснование:** Для единообразного приёма заявок через Google Sheets.

**Детали реализации:**
- Каждый пилот получает свой `apply.html` и `form.css`.
- Все формы отправляют в один Google Apps Script endpoint (MVP endpoint).
- Каждая форма помечает себя в `source` field для логирования источника заявки.

**Результат:** Unified form submission, easy tracking of pilot-specific inquiries.
